  17(offer)이고, 7일 유지 보너스가 곧 풀 유동성 공급 장치다.

## 재미 논거 (설계 근거 기록)

1. **핑계 메커니즘** — "관상이 천생연분이래서"라는 제3자 핑계가 발신·수신 양쪽의
   자기노출 부담을 제거. 케미 그룹 베스트 매칭 공개와 동일 원리의 1:1 저비용 버전으로,
   6인 모집이 필요한 케미 그룹 아래를 받치는 저조정비용 루프.
2. **체크 루프 = 복권** — 무료·즉답·확률 ~10%.
3. **수신 희소가치** — 1일 1건 제한이 "누군가 오늘 나를 골랐다" 알림의 가치를 보존.

## 신규 천생연분 푸시 (17 스코프 포함)

새 2단계 opt-in 유저가 들어올 때 기존 유저와 천생연분이 발견되면 해당 기존 유저에게
푸시 ("새로 올라온 관상 중 천생연분이 있습니다"). 결정적 엔진의 약점(점수 불변)을
재방문 트리거로 역전 — 신규 1명 × 풀 N 의 O(N) 계산이라 배치·가속 불필요.

## 구현 스케치 (착수 시 상세화)

- **DB**: opt 컬럼 2단계화 (출시 전이라 drop-recreate 자유), `chat_offers` 테이블
  (sender·receiver·status·expires_at + 거절 영구 기록), 1일 1건은 서버 강제.
- **궁합 재계산 위치**: 엔진이 Dart/JS 라 Supabase RPC 안에서 못 돌린다 → offer
  발신은 Worker endpoint 경유 (Flutter → Worker 가 face_engine.js 로 등급 검증 →
  service key 로 offer insert). 체크(등급 조회)도 같은 endpoint 재사용.
- **앱**: 오늘의 관상 화면(체크 UX) · offer 수신함(매칭 제안 시트 패턴 재사용) ·
  설정 opt-in 2단계 확장 · terms §7 개정.
- **심사 노트**: abuse control 명시 — 천생연분 게이트 + 1일 1건 + 72h 만료 + 차단·신고
  + 양방향 opt-in.
- **빈 결과 카피**: "오늘은 천생연분이 없습니다. 내일 새 관상이 올라옵니다" —
  측정 가능한 사실만.

## 열린 결정 (착수 시)

- 앱 내 화면 위치 — 관상 탭 섹션 vs 별도 진입점.
- offer 1코인 유지 여부 — 한도(1일 1건)와 이중 장벽이 과하면 발신 무료화 검토.
- 2단계 동의 문구 최종안 + terms 개정안.
