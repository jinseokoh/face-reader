#### 노출 규칙 — 기여도 리포트를 어디까지 쪼개 보여주나

| pillar | 리포트 표시 |
| --- | --- |
| P1~P4 · P6 | pillar 총점을 보여주고, **문항마다 두 사람의 답이 같았는지 달랐는지와 그 점수**를 함께 보여준다 |

## 2. 매칭 계산

```
문항 점수    = S_q[answer_a][answer_b]        // 선택지 유사도 행렬
pillar 점수  = mean_answered(문항 점수) × 100
rawTotal    = mean(활성 pillar 점수)
spread      → _remapToUserScale               // 기존 파이프라인 재사용
```

정답/오답 이분법은 계단이 심해서 유사도 행렬을 쓴다. 5점 척도 문항은 `S = 1 − |a−b|/4` 자동 생성, 나머지는 상수 테이블(콘텐츠 작업).

**⚠️ 대각을 1.0 으로 고정하지 않는다.** 취향 문항은 일치가 궁합이지만 **역할 문항은 상보성이 궁합**이다 (P3 Q1·Q4). 행렬 전체를 손으로 채운다.

라벨 경계(56/78/90)와 4단 라벨은 유지 — 점수 체계가 pillar 구성에 따라 흔들리면 안 된다.

**pillar 별 정규화** — `_remapToUserScale` anchor 는 궁합 엔진 분포에 튜닝돼 있다. `compat_sub_display.dart` 가 이미 sub-score 마다 별도 anchor 테이블을 두고 각자의 MC 분포로 0~100 에 꽂는다. **같은 패턴을 pillar 에 복제한다** (pillar 별 MC 실행 → anchor 추가).

## 3. 기여도 리포트

> **산수를 펼쳐 보이는 앱은 점술일 수 없다.** 4.3(b) 반박의 물증이자 코인 unlock 지점.

총점 파이프라인이 비선형이라 raw 기여도를 나열하면 합이 총점과 안 맞는다.

```
기여도_표시(i) = 기여도_raw(i) × (총점_표시 / 총점_raw)
```

리포트는 두 단계로 보여준다.

- **pillar 단계** — 각 pillar 가 총점에 얼마를 기여했는지
- **문항 단계** — 그 pillar 안에서 문항마다 두 사람의 답이 같았는지 달랐는지와 그 점수 (P5 는 이 단계를 보여주지 않는다, §1.6)

각 줄은 **문항 이름 · 두 답의 관계 · 점수** 세 칸으로 쓴다. 답이 같았던 문항뿐 아니라 **달랐던 문항도 보여준다** — 리포트가 정직해지고 대화거리가 거기서 나온다.

P6 는 기존 4 sub-score 로 자동 분해되고, 문장 근거는 `compat_finding.dart` 가 이미 생성한다.

| 카드에 넣는다 | 넣지 않는다 |

| 방 제목 · pillar 배지 · 인원 · 마감 시간 · 방장 닉네임 | 참가자 얼굴 격자 · 프로필 직행 · 거리 표시 · 성별·나이 탐색 필터 |

`match`(남녀 반반) 유형은 유지하되 기본값 아님.

### 4.4 죽으면 안 되는 것

| | 조치 |
| --- | --- |
| 궁합 1🪙 unlock | **기여도 리포트 unlock 으로 이전** (전환 모수가 더 크다) |
| 관상 공유 `/r/{id}` | 진입점은 묻되 라우트·산출물 생존 |
| `/g/{id}` 웹 초대장 | 그대로 |

### 4.5 얼굴 없는 방

아바타가 라이브 `my-face` 사진이고 매칭 성사 연출이 사진 상호 공개다. 얼굴 없는 방에선 **닉네임 + 생성 아바타**로 분기한다. 생성 아바타가 신규 작업.

#### 플랫폼별 브랜드 분리

**Android 는 `관상은 과학이다` 를 그대로 유지한다.** 앱 이름은 플랫폼별 설정이라 독립이다.

| | 지금 | 바꿀 값 |

| Android Play Console 이름 | 관상은 과학이다 | **무변경** |
| iOS `Info.plist` `CFBundleDisplayName`·`CFBundleName` | 관상은 과학이다 | `facely.kr` |
| iOS App Store Connect 이름 | — | `facely.kr` |
| **웹 `facely.kr` 전체** | 관상은 과학이다 | **`facely.kr` 로 통일** |

웹을 통일하는 이유 — iOS 리스팅의 마케팅 URL 이 `facely.kr` 이라 심사관이 클릭 한 번에 도착한다. 기기별 분기는 User-Agent 를 바꾸면 드러나므로 쓰지 않는다.
